# 助手能力评测与验收

## 可重复执行

先加载 Node 24。`pnpm ai:evaluate --out=.data/ai-evaluation/dry-run` 只生成 50 个合成案例与评分表，不调用模型。案例覆盖五模块各 10 个，其中 30 个为四轮交流，`demo: true` 为 10 个领导演示案例。

真实评测显式运行：

```bash
pnpm ai:evaluate --run --repeats=3 --out=.data/ai-evaluation/current
node --import tsx scripts/ai-evaluation/report.ts .data/ai-evaluation/current
```

可用 `--module=learning_problem`、`--case=learning_problem-03`、`--demo` 缩小范围。密钥沿用环境配置；结果只含合成数据。记录答案、工具结果、退出原因、耗时、用量和模型/参数/提示词/图/场景/知识夹具/校验代码的版本摘要。原始运行结果保存在本地忽略目录，不进入普通产品日志。

基线可通过 `--graph=/绝对路径/baseline-graph.ts --prompt=/绝对路径/system.txt` 使用冻结的旧图及提示词；基线与新版必须使用相同场景、模型参数和合成知识版本。此比较覆盖真实模型、Agent 图、流式句子处理和回答校验；不模拟数据库摘要压缩或 HTTP 权限。这些边界另由单元、集成及浏览器测试验证。

## 人工盲评

`report.ts` 生成 `scores-template.csv`；复制后让业务负责人和一线教师分别填写。先隐藏版本标签、随机排列答案，再独立打分：专业性与可执行性各 1—5 分；多轮是否接受纠正、记住限制、不重复失败建议；逐项记录可核查事实和正确数；记录任何编造制度、等级或分数。分歧逐项复核，不以模型自评代替人工评分。

门槛：每模块专业性/可执行性均分 ≥4；多轮行为通过率 ≥90%；事实准确率 ≥95%，且不得编造正式制度/分数/等级。权限、对象和异常处理必须全部通过。普通回答首个可读内容 P95 ≤基线 1.2 倍，高风险回答单独统计。执行成功只代表完成了运行，不代表上述业务质量通过。

## 领导演示

每模块演示 `01`（信息不全→补充具体处境→限制→下一步）和 `02`（已试过→失败反馈→新证据→调整动作），共 10 个案例。先展示同一问题旧版与新版，再检查答案的事实依据、下一步动作与观察指标。逐轮原文见 `scenarios.json`，无需背诵固定答案。

工具故障、知识缺失、对象切换、历史评估和已有方案也在同一评测集。每个确认的问题增加合成回归，不把教师真实聊天复制进测试材料。知识缺口只记录模块与原因的运营事件，由人工确认后走现有三库审核发布流程。

## 适用范围

助手提供分析、建议和已授权记录的导航；量表计分、分级、归因、安全熔断与业务写入仍由原有确定性代码和页面完成。语义校验可能误拦截或漏检，测试通过不能保证所有真实场景无误。校验失败、超时和停止生成不得作为正常回答落库。
