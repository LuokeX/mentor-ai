# AI 助手与业务知识库使用说明

## 1. 定位

首页“AI 赋能助手”不是通用聊天机器人，而是受教师赋能业务模型、安全规则和权限约束的多轮助手。它负责理解教师描述、按模块检索已审核资源、生成带来源的可执行回答并建议处理模块；量表计分、业务分级、危机熔断和管理员授权仍由确定性代码执行。

当前可执行模块以代码中的 `moduleIdSchema` 为准：自我成长、班级系统、家校沟通、学生个体问题、学生学习问题。不得在没有明确业务依据和确定性规则的情况下新增模块。

## 2. 处理链路

```text
教师输入
  → 本地危机关键词和硬规则
  → DeepSeek 语义风险辅助（配置模型时）
  → 姓名、电话、邮箱等信息脱敏
  → 确定主模块和次模块
  → 优先检索本校已发布模块资源，再回退平台已发布资源
  → 读取当前教师最近多轮会话
  → DeepSeek 生成回答、模块建议和引用编号
  → Zod 校验输出并过滤非法引用
  → 输入/回答/来源/模型模式加密存档
  → 教师确认模块
  → 确定性评估、分级、方案和工具
```

任一红线命中后立即停止常规回答，先创建风险事件、心理专员工单、通知 Outbox 和审计记录。

## 3. DeepSeek 配置

在 `.env` 中配置：

```env
DEEPSEEK_API_KEY=实际密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_ROUTER_MODEL=deepseek-v4-flash
DEEPSEEK_GENERATOR_MODEL=deepseek-v4-pro
DEEPSEEK_TIMEOUT_MS=8000
```

修改后重新启动 App。教师首页会显示“DeepSeek 已接入”或“本地降级模式”。没有密钥、超时、响应为空或 JSON 校验失败时，系统自动使用本地安全路由和知识摘录，不会把模型故障暴露成无响应页面。

DeepSeek 只负责路由辅助和回答表达，不负责知识向量。本版使用校内 Ollama 的 `qwen3-embedding:0.6b` 生成 1024 维向量，存入 PostgreSQL pgvector；查询时融合向量余弦近邻、`pg_trgm`、中文二元词、标题和章节权重。精确业务代码与语义近义表达因此都能参与召回。Ollama 超时、停机或返回非法维度时自动退回原关键词检索，不影响安全规则和教师基本使用。

Embedding 配置：

```env
EMBEDDING_ENABLED=true
OLLAMA_BASE_URL=http://localhost:11434
EMBEDDING_MODEL=qwen3-embedding:0.6b
EMBEDDING_TIMEOUT_MS=8000
```

Docker Compose 内 App 使用服务地址 `http://ollama:11434`，端口只绑定服务器回环地址，不向校园网或公网直接开放。文档向量与查询向量必须使用同一模型；修改 `EMBEDDING_MODEL` 后执行 `pnpm knowledge:reindex` 重新生成全部旧向量。

## 4. 模块资源中心

平台后台“模块资源中心”按 `module + libraryType + scope` 管理资源库，`libraryType` 包括：

| 类型 | 用途 | 是否允许 AI 自由补充 |
|---|---|---|
| `assessment` | 题库、说明和版本 | 否，计分仍由确定性代码执行 |
| `rules` | 分级、阈值、红线和平台要求 | 否，必须同步确定性规则 |
| `tool` | 工具卡、步骤、禁忌和来源 | 否，必须引用已发布资源 |
| `professional_knowledge` | 专业知识与业务手册 | 可用于解释，但引用必须真实 |
| `sop` | 流程、升级路径、职责边界 | 否，必须引用已发布资源 |
| `script` | 沟通话术和场景表达 | 否，必须引用已发布资源 |
| `case` | 去标识化案例和示例 | 否，必须引用已发布资源 |
| `prompt` | 模块提示词和资源策略 | 否，仅平台管理使用 |

教师运行时统一使用资源解析器：先读取本校 `published` 版本；同一模块与库类型没有校本版本时，再回退平台 `global published` 版本。`draft` 和 `retired` 不会进入教师端和 AI 检索。

涉及工具、SOP、制度、平台要求、量表、分级、红线时，如果没有命中已发布资源，AI 必须提示“需要进入模块评估或补充业务知识后确认”，不能编造平台规则或虚构来源。通用支持建议可以不给引用，但不能包装成制度、SOP 或量表结论。

旧 `content_packages` 与 `knowledge_bases` 保留为兼容来源。执行数据库迁移后，可用 `pnpm resources:migrate` 将已发布内容包和旧知识库回填到模块资源中心；脚本可重复执行，不修改已提交历史 migration。

## 5. 平台后台导入知识

旧入口仍可用于兼容导入。新资源优先使用“平台管理后台 → 模块资源中心”创建资源库、版本和文档。

使用平台管理员账号进入“平台管理后台 → AI 知识库”：

1. 页面顶部可查看知识库、在线库、文档和知识片段统计；使用名称、状态和范围筛选快速定位内容。
2. 创建知识库，填写名称、说明和使用范围。
3. 选择全平台或指定学校。校级知识不会被其他学校检索。
4. 选择知识库并上传 `.md`、`.markdown`、`.txt` 或 `.json` 文件。
5. 确认文件不包含学生、家长或教师个人业务数据。
6. 系统自动规范化文本、计算校验和、按章节分块并调用 Ollama 生成向量。
7. 在知识库详情中点击文档，可预览教师助手实际检索的标题、片段和 Token 估算。
8. 导入后的文档为草稿，必须由平台管理员确认并点击“发布”。
9. 只有 `published` 知识库中的 `ready` 文档会进入教师回答。

单文档上限为 1 MB。同一知识库中内容校验和相同的文件不能重复导入。

删除文档会同时删除其知识片段并写入审计日志。为避免教师端在线知识被误删，已发布知识库不能直接删除文档；应先停用知识库、删除或调整内容，再重新发布。

## 6. 命令行导入

服务器或本地也可以使用受控 CLI 导入：

```bash
pnpm knowledge:import /absolute/path/manual.md \
  --confirm-no-personal-data \
  '--name=家校沟通业务手册' \
  --publish
```

导入指定学校的校本知识：

```bash
pnpm knowledge:import /absolute/path/school-policy.md \
  --confirm-no-personal-data \
  '--name=校本处置规范' \
  --school-code=demo-school \
  --publish
```

CLI 默认使用 `platform.admin@demo.local` 作为审计操作者；非演示环境必须使用 `--actor-email=正式平台管理员邮箱`。所有 CLI 导入都会写入平台审计日志。

## 7. 发布状态

| 状态 | 是否可检索 | 说明 |
|---|---|---|
| `draft` | 否 | 新建知识库或待审核内容 |
| `published` | 是 | 教师助手可以按租户范围检索 |
| `archived` | 否 | 整个知识库立即退出检索 |

向已发布知识库导入新文档时，新文档保持草稿，旧的已发布文档继续可用；再次发布后新文档才进入检索。

## 8. 回答引用与审计

- 模型只能返回本次检索结果中存在的知识片段或资源片段 UUID，服务端会丢弃模型虚构的引用。
- 教师界面展示知识库或模块资源库、资源类型、模块、文档标题、章节和摘录。
- 会话历史只允许所属教师读取，消息正文继续使用 AES-256-GCM 加密存储。
- 模型调用日志只记录提供方、模型、用途、耗时、Token 数和错误码，不记录教师原文或完整 Prompt。
- 知识创建、导入、发布、停用和 CLI 导入均写入平台审计日志。

## 9. 知识内容规范

允许导入：经审核的业务手册、SOP、工具卡、话术、题库说明、校本制度和产品规则说明。

禁止导入：真实学生/家长/教师个案、聊天记录、手机号、身份证号、医疗记录、投诉原文、账号密钥、未经授权的版权材料，以及与教师赋能业务无关的通用互联网资料。

业务知识应尽量使用清晰 Markdown 标题，一个章节只描述一个主题，并明确适用场景、禁止事项、升级条件和来源版本。红线与计分阈值即使写入知识库，也必须同步编码到确定性规则并经过测试，不能只依赖模型阅读文本执行。

## 10. 当前边界和后续扩展

当前已支持：多轮历史、知识导入、模块资源库、草稿/发布/停用版本流转、全局/校级覆盖、Ollama Embedding、pgvector + 关键词混合检索、来源引用、DeepSeek 回答、模型降级和调用审计。

尚未包含：PDF/Word/OCR 解析、资源审批双人复核、资源片段在线编辑、检索反馈自动调权和独立重排序模型。这些能力应在业务手册、模型供应商和合规边界确认后增加。
