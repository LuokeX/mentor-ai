## 结论（先看这一段）

**是，而且影响是直接且可验证的，不是「读起来别扭」这种程度的问题。**

三库不是参考资料，它是运行时的**唯一业务内容来源**：

- 「工具-步骤明细」的正文经 `renderToolContent()` 直接落进方案的「使用工具「X」」动作，也是 AI 改写步骤与 AI 深度报告的输入；
- 「归因-建议动作」直接变成方案动作标题「针对「X」」的正文，同时是 AI 报告 `facts.actions` 的输入；
- 「分级规则」的等级、等级中文名、严重度、熔断位决定方案走哪条路、摘要写哪一段；
- 知识库原文是首页 AI 助手 `knowledge_search` 工具**唯一**可引用的平台依据。

## 一、分级规则（等级 / 严重度 / 干预动作）

这一层决定方案的走向，问题也最集中。

### 1.1 触发条件被写成恒真式

`server/domain/rules-executor.ts` 的等级判定是「按 `pri` 升序，命中第一条即停，最后一条兜底」。因此一条恒真的规则会**吃掉它后面所有规则**。

已确认的恒真条件：

```
student_case SC_GR_02（pri=20，orange/high）
when: 题[q1] >= 3 且 题[q2] >= 3 或 维度[SC_S1D6] <= 7 或 ... 或 总分 >= 140 或 总分 <= 169
                                                              ^^^^^^^^^^^^^^^^^^^ 恒真
```

`总分 >= 140 或 总分 <= 169`：该量表总分区间是 45–225，任何取值都满足其一。看写法应该是想写「140 到 169 这一档」（即 `且`），被拆成了 `或`。

同类还有：
- `SC_GR_03`「`总分 >= 115 或 总分 <= 139`」、`SC_GR_06`…`SC_GR_18` 共 13 条同样句式
- `home_school HS_GR_02`「`总分 >= 32 或 总分 >= 23 或 总分 <= 27 或 总分 >= 32`」
- `home_school HS_GR_03`「`总分 >= 27 或 总分 >= 18 或 总分 <= 22 或 总分 >= 25`」
- `home_school HS_GR_04`「`总分 >= 20 或 总分 >= 13 或 总分 <= 17 或 总分 >= 18`」
- `class_system CS_GR_02`「任一维度均分 `<= 3`」——随机取样命中率 **98.4%**，等价于「几乎是个人就判橙色/高」

### 1.2 不可能命中的条件

- `student_case SC_EV_38`：`维度[SC_S1D1] >= 22`，但 `SC_S1D1` 只有 2 道题（上限 10 分）→ 数学上不可能
- `student_case SC_EV_65`：`维度[SC_S1D3] >= 22`，该维度只有 3 道题（上限 15 分）→ 不可能
- `learning_problem LP_GR_AUTO_01/02/03`：条件写 `均分 >= 4` / `>= 3.5` / `>= 3`，但 `LP_S1`（SNAP-IV）是 0–3 计分 → 几乎不可能（且 3 条互相遮蔽）

这批 `*_AUTO_*` 规则看起来是批量生成的兜底档，条件用的是统一模板 `均分 >= X`，没有对照各量表的分制与方向。

### 1.3 「死规则」实测（永远不可能被命中）

判定方法：对每张量表做极值模式取样 + 4000 次按选项均匀随机取样，统计从未出现在结果里的规则。

| 模块 | 分级规则 | 其中死规则 | 证据规则 | 其中死规则 |
| --- | --- | --- | --- | --- |
| self_growth | 5 | 0 | 31 | 0 |
| class_system | 3 | 0 | 21 | 0 |
| home_school | 75 | **50** | 56 | 7 |
| student_case | 19 | **17** | 69 | 3 |
| learning_problem | 17 | **3** | 37 | 0 |

home_school 的 50 条死规则中，47 条是 `HS_GR_AUTO_*`，另外 3 条是 `HS_GR_03/04/05`（被 pri=20 的 `HS_GR_02` 恒真条件遮蔽）。AUTO 系列被挂在**家校沟通红线检查（HS_S2）**上，条件是「均分 >= 3」，而同一个量表上 pri=60 的 `HS_GR_06`（任何一项为「是」即红）已经先命中，AUTO 系列全部成为不可达代码。

### 1.4 等级名与等级值/严重度互相矛盾

`level` 是给机器和颜色用的键，`levelName` 是给教师看的中文名，两者必须一致。实测冲突：

| 模块 | 冲突 |
| --- | --- |
| student_case | `SC_GR_06`–`SC_GR_18` 共 13 条，`level` 分别是 red/orange/yellow/blue/green，`levelName` **全部**是「黄色-中响应」；其中 `SC_GR_06/11/16` 是 `level=red, severity=crisis`，教师看到的却是「黄色」 |
| home_school | 同一个 `red` 对应两个名字：「E级（危机干预）」与「5级·极重（危机干预）」；同一个 `orange` 对应「D级」与「4级·重度（强化干预）」 |
| home_school | `green`（低风险/健康）的名字是「PSTAR聚焦不足（关注）」与「健康观察（兜底）」——名字语义与等级相反 |
| student_case | `SC_GR_05` 是 `green` 但名字叫「紫色-待观察」，而全库**不存在** purple 这个等级值 |
| class_system | `green` 叫「健康观察（兜底）」，`orange` 叫「需关注维度」——命名风格不统一 |

### 1.5 高严重度等级没有干预动作

`executeRules` 的等级通道是「命中等级的 `interventionActions` 逐条变成方案动作，标题为『按「等级名」干预』」；动作为空时该通道什么都产不出。

- 119 条分级规则中 **86 条干预动作为空**
- 其中 `severity = high | crisis` 的有 **22 条**：self_growth 2 条（`SG_GR_01`、`SG_GR_02`）、home_school `HS_GR_AUTO_01/05/…` 共 16 条、learning_problem `LP_GR_AUTO_01/04/07/10` 4 条

后果：教师命中 high/crisis，方案里只有一条没有正文的标题，或者干脆没有这一条（`plan-action-enhancement.ts` 会过滤掉 `detail` 为空的动作，AI 改写也不会补）。

有干预动作的 33 条里，student_case 的 13 条正文完全相同：

```
干预动作1: 启动标准诊疗流程（S1→S2→S3→S4）
干预动作2: 使用对应编码的干预技术，按月记录进展
```

「S1→S2→S3→S4」是内部流程编号，教师看不懂；13 条规则共用同一句话，等于没有分层干预。

### 1.6 提交时直接报错

```
home_school HS_S10（九级情感容器评估）
命中 HS_EV_48（条件：容器总分 >= 36 且 紊乱型均分 >= 4）
→ 抛错：证据规则 'HS_EV_48' 求值失败：Unknown variable '紊乱型均分'
```

`submit.post.ts` 调用 `executeRules` 时没有 try/catch，该错误会冒泡成 500，教师**无法提交这份评估**。实测在随机取样下 home_school 出现 88 次执行报错。

### 1.7 模块级等级分布实测（按选项均匀随机取样）

| 量表 | 实测分布 | 说明 |
| --- | --- | --- |
| self_growth SG_S1 | green 81.8% / red 14.8% / orange 3.4% | 无 yellow、blue |
| self_growth SG_S2 | **green 100%** | 「明显消耗」永不出现 |
| self_growth SG_S3 | blue 57.9% / green 42.1% | 无 yellow/orange/red |
| class_system CS_S1 | **orange 98.4%** / green 1.3% / red 0.3% | 「需关注维度」近乎恒真 |
| home_school HS_S1 | yellow 60.0% / orange 39.2% / blue 0.8% | 无 green |
| home_school HS_S2 | red 99.7%（熔断） | 8 项红线勾选，勾中任意一项即熔断——**需业务确认是否本意** |
| learning_problem LP_S1 | green 98.6% / red 1.4% | 中间三档全死，量表实际退化成二值 |

## 二、归因库「建议动作」

113 个归因项全部填了建议动作，无空值、无跨项重复——这一项基础是好的。问题在写法与引用。

### 2.1 硬错误：student_case 建议动作引用的工具编号不存在且自相矛盾

student_case 工具库的编码是 `SC_RX_01`…`SC_RX_31`，但建议动作里引用的是 `T1`…`T12`，**全部不存在于工具库**。而且同一份数据里编号映射互相打架：

| 归因项 | 引用的编号 | 实际指的工具 |
| --- | --- | --- |
| `SC_AT_09` 低自尊型 | T8 | 优势发现日记 |
| `SC_AT_16` 自我意识 | T6 | 优势发现日记 |
| `SC_AT_09` 低自尊型 | T11 | 优势锚定法 |
| `SC_AT_16` 自我意识 | T9 | 优势锚定法 |
| `SC_AT_18` 情绪管理 | T12 | 心智化回应 |
| `SC_AT_16` / `SC_AT_17` | T10 | 心智化回应 |
| `SC_AT_19` 人际关系 | T8 | 友谊桥同伴配对（与 AT_09 的 T8 冲突） |

教师会看到「用 T8 优势发现日记…」这类正文（AI 改写前、或 AI 未全覆盖导致展示原文时）；AI 改写时这段文本是输入，模型被要求「关键事实不变」，很可能把 `T8`、`T11` 原样带进方案。

### 2.2 同一套数据里并存三种写法

| 模块 | 写法 | 示例 |
| --- | --- | --- |
| self_growth / home_school（前 5 条） | 完整句子，带时间与数量 | 「本周内安排两段各 30 分钟的不可打扰恢复时段，并减少一项非必要班务承接」 |
| class_system | 电报体，分号串联 | 「每日1次非评价性打招呼；设固定谈心时间(10min/周)；用「先跟后带」接住情绪再谈事」 |
| student_case | 项目符号 + 内部编号 + 一段话 | 「•T6优势发现日记——每天帮学生记录一件「最小但真实」的成就…•配合T9优势锚定法：…•使用T10心智化回应的「看见」技术——…」（单条 100–300 字） |
| learning_problem | 短动词短语 | 「同伴支持配对+合作任务设计」「焦虑疏导+家长沟通降低评价压力」 |

`student_case SC_AT_16`–`SC_AT_21` 还有一个结构问题：这 6 条归因项的名字是「自我意识」「社会适应」「情绪管理」「人际关系」「学习习惯（6D）」「生涯认知」——它们是**维度名**，不是归因名，和 `SC_AT_01`–`SC_AT_15`（「注意力分散型」「焦虑退缩型」…）显然不是同一批人、同一套口径写的。

### 2.3 空泛到无法执行

```
home_school HS_AT_06 沟通质量不足  → 「建立定期反馈节奏，优化沟通方式」
home_school HS_AT_07 角色边界模糊  → 「明确家校责任边界，建立分工约定」
home_school HS_AT_09 危机响应滞后  → 「建立突发事件快速响应机制和应急预案」
home_school HS_AT_13 社会层因素主导 → 「建立多方协作机制，完善制度化沟通渠道」
learning_problem LP_AT_02 执行功能薄弱 → 「开展认知训练（注意力/记忆/执行功能）并配合课堂支持」
```

这些会原样成为方案动作「针对「沟通质量不足」」的正文——没有对象、没有时间、没有可观察的完成标志。

### 2.4 术语绕口

方案动作标题会写成「针对「X」」，X 直接取归因名。以下归因名对一线班主任不友好，且不带解释：

- 「学业堰塞」「动力错配」「个体情绪失接」「氛围负向」（class_system）
- 「认知锁定」「防御退缩」「双重依恋困境」「冒名顶替综合征」「基本心理需要受挫」（self_growth）
- 「三层叠加恶性循环」「情感容器临界/损耗/破裂」（home_school）
- 「元系统思维薄弱」「外控动机主导」（learning_problem）
- 「三年级知识断层」（把年级写进了归因名，换年级即失效）

另有一处专业表述需要核实：「用 73855 法则沟通」（class_system `CS_AT_03`）。麦拉宾（Mehrabian）7-38-55 结论的适用范围是**态度/情感类信息的传递**，把它当作一般沟通法则使用是被广泛批评的误用，建议改成可直接执行的动作。

## 三、工具库「结构化步骤」

### 3.1 标题被硬截断成半句话（366 条）

实测 1049 条结构化步骤中，366 条的 `title` 是 `description` 的前缀且长度恰为 24 字——说明生成时按固定长度截断。因为标题与说明**同时渲染**（`renderToolContent`：`N. {title}: {description}`），方案里出现的是：

```
1. ①拿出一张纸，画两个圆圈：；- 内圈（我的责任圈: ①拿出一张纸，画两个圆圈：；- 内圈（我的责任圈）：我直接可控的事；…
2. ④对外圈的事：写下'我可以做XX来施加影响，但结: ④对外圈的事：写下'我可以做XX来施加影响，但结果不完全取决于我'
3. ⑤对圈外的事：写下'这不是我的责任，我需要练习放: ⑤对圈外的事：写下'这不是我的责任，我需要练习放手'
```

这是**已确认在生产数据里出现过的文本**（开发库中 `ai_actions_status=done` 的方案里就是这种形态）。

### 3.2 标题与说明完全相同（683 条）

同一原因的另一面：683 条步骤 `title === description`，渲染后退化成单行、无细节。`scripts/backfill-tool-action-steps.ts` 里已经记录过这个现象（"工具库发布版 4.5.0 起的 structuredSteps「步骤说明」与「步骤标题」被填成相同文本"），说明**源头数据至今未修正**，只做了下游清洗。

### 3.3 扁平 `steps` 碎片化（163 个工具）

原始步骤文本按标点被切成多行，导致一条步骤变成若干碎片：

```
"①用鼻子吸气" / "默数4秒" / "感受腹部鼓起"
"- 必须我做 = 5分" / "- 最好我做但别人也行 = 3分" / "- 别人也能做 = 1分"
"⑧你觉得我们年级组/教研组最需要改进的是什么？；使用规则：；- 两个人轮流抽卡…"
```

还有 4 个工具的编号重复或错乱（SG_RX_33、SG_RX_47、SG_RX_50、SG_RX_63）。

### 3.4 辅助字段几乎全空

1049 条结构化步骤中 **994 条**没有任何「预计耗时 / 关键提示 / 话术模板 / 成功标准 / 所需材料 / 常见问题」。也就是说 ⑦b 表虽然设计了 10 列，实际只用了「步骤标题 / 步骤说明」两列——这正是 AI 改写任务描述里说的「机械条目」的来源：AI 拿不到话术、耗时、达标标准，只能自己补。

工具主表也有缺项：220 个工具中 30 个无「关键话术」、59 个无「单次耗时」、49 个无「疗程与频次」。

### 3.5 内部编码残留

工具正文里出现 `（RX-011）`、`（RX-020）`、`（RX-066）` 这类内部编号，与工具库自身的编码体系（`SG_RX_xx`）不一致，教师无法对应。AI 改写后仍会保留（因为它被要求「关键事实不变」）。

### 4.1 student_case：19 条模板只有 2 种正文

```
出现 15 次的模板（RED_1 / ORANGE_2 / YELLOW_3 / BLUE_4 / RED_6 / ORANGE_7 / YELLOW_8 /
BLUE_9 / RED_11 / ORANGE_12 / YELLOW_13 / BLUE_14 / RED_16 / ORANGE_17 / YELLOW_18）
```

19 条模板覆盖 5 个等级，实际只有 2 种正文；从编号规律看是按批次复制（每批 red/orange/yellow/blue/green 各一条），但正文从未按等级区分。一个被判为 red、已熔断转介的教师，方案摘要第一句写的是「本次评估判定为黄色·中响应」。

### 4.2 home_school：两套等级命名体系错配

模板同时存在「A–E 级」与「1–5 级」两套文案，且**排序靠前的先被选中**（`selectOutputTemplate` 先按等级、再按 `order`）：

| --- | --- | --- | --- |
| red | `TPL_HS_RED_1`（order=1） | 「触发 E 级保护通道」 | `HS_S2` 红线的等级名是「5级·极重（危机干预）」 |
| orange | `TPL_HS_ORANGE_2`（order=2） | 「沟通风险等级为 D 级」 | `HS_S1` 的等级名是「4级·重度（强化干预）」 |

| blue | `TPL_HS_BLUE_4` | 「需要一定铺垫」 | `HS_S1` 的等级名是「2级·轻度（普及干预）」 |

### 4.3 learning_problem：模板里写死的阈值与实际规则不符

模板正文写「SNAP-IV 筛查提示…（任一组≥6项≥2分）」「学习策略评估显示策略使用薄弱（总均分≤2.5）」「成绩趋势显示存在薄弱或下滑信号（低于班级均值或连续下滑）」，而实际规则是 `LP_GR_01: 维度[LP_S1D1] >= 2 且 维度[LP_S1D2] >= 2`、`LP_GR_03: 总分 >= 3.5`——两者不是同一个判据。教师会同时看到模板里的阈值和确定性判级结果，无法对上。

### 4.4 class_system：模板混用两套口径

`TPL_CS_ORANGE_2`：「五系统任一维度均分<3.0（系统分<9）标记为"需关注维度"（最薄弱：${最薄弱维度}）；或C级（中度困扰）点检命中」——把「五系统分级」与「A–E 点检」两套体系塞进一句话。

## 五、知识库原文（1036 篇）

### 5.1 规模与结构

- 全部 1036 篇的 `libraryType` 都是 `knowledge`，且都是**独立文档**（不挂三库版本）
- 正文长度：最短 66 字，中位数 324 字，P90 611 字，最长 3314 字
- **234 篇不足 200 字**——对「知识库原文」而言更像卡片而非原文

### 5.2 三库内容被渲染成知识文档，混进检索池（28 篇）

以下标题是渲染三库 payload 生成的，不是业务原始知识：

```
输出模板·red/orange/yellow/blue/green/none·summary（6 篇）
分级规则·状态平稳/需关注/需立即关注/需重点支持/观察+轻支持（6 篇）
红线·R1 自伤自杀相关表达 … R7（7 篇）
路由·职业耗竭/家暴虐待/未成年学生安全/精神障碍症状/自杀意念（5 篇）
禁忌·互动模式 = A型/B型/C型/AS分档（4 篇）
```

后果：`knowledge_search` 会把「红线：R1…熔断后动作」「分级规则：状态平稳（命中等级=none）」这类**内部运行规则**当作知识片段交给模型，教师可能直接在 AI 回答里看到平台内部规则表述（含「S1→S2」「L1–L3」「R类/O类/Y类命中数」这类编码）。

### 5.3 未替换占位符与 None 残留

- 2 篇正文含 `${...}`：`输出模板·orange·summary`、`输出模板·yellow·summary`，例如「评估显示，您在「**${主要归因}**」上的信号较为突出…」
- 4 篇正文含 `None`：`分级规则·状态平稳`（「**依据量表**：None　**严重度**：low」）、`家长沟通压力量表（PCS）`、`依恋安全感快筛（AS-3）`、`HERO心理资本自评（PCQ-12简版，12题）`

### 5.4 文档描述的规则，引擎不会执行

`五问自评` 文档「## 详细解释」写：

> 评分处理：总分≥20 或**任何单项≥4**启动支持响应；总分≤10 且各项≤2 维持正常观察；Q1 和 Q3 同时高分或出现自伤/自杀表达立即启动危机响应（红色）；**Q3 连续 4 周≤2 触发紫色预警**。

已发布的 self_growth 分级规则只有 5 条：`red = 题[q1]>=4 且 题[q3]>=4`、`orange = 总分>=20`、`yellow = 总分<=31（依据 SG_S2）`、`blue = 维度[SG_S3D1]>=3（依据 SG_S3）`、`green = 兜底`。

- 「任何单项≥4 启动支持响应」——没有这条规则
- 「紫色预警」——全库（五模块 119 条规则）**不存在 purple 等级**
- 但知识库里有 12 篇文档提到「紫色预警」，包括标题就叫「紫色预警」「L1·紫色·待观察」的两篇

**AI 回答平台制度、量表、SOP 这类内容时只依据工具检索返回的结果，而检索返回的正是这些与引擎不一致的阈值描述——模型会把这些当作平台事实转述给教师。**

### 5.5 「智能体回复示例话术」78 篇

78 篇概念文档的最后一节是「## 智能体回复示例话术」，内容是写成第一人称、给 AI 直接照念的话术，例如：

> 五问自评是一个3分钟以内的快速小工具，五个问题分别看你的情绪状态、角色边界、意义感、效能感和同伴支持。它不是诊断，而是帮你快速了解自己目前的状态需不需要更多支持。每季度做一次就行…

这类文本被检索到后，模型极易整段复述：回答风格被固定住（同一段话术在不同问题下重复出现），而且会把上面 5.4 里那些与引擎不符的阈值一并带出。

### 5.6 切片来源标题错配（659/1027）

`chunkModuleResourceDocument` 用一个滚动的 `heading` 变量，文档不足 1300 字时只产出**一个切片**，而该切片的 `heading` 是文档中**最后一个**小节标题。实测：

- 1027 篇是单切片文档
- 其中 **659 篇** `heading ≠ 文档标题`
- 最集中的取值：`适用场景`(240)、`禁止事项`(85)、`智能体回复示例话术`(78)、`关联工具/资源`(22)、`关联工具`(22)、`相关术语`(12)

例如「转介话术」这篇的唯一切片，`heading` 是「禁止事项」，正文却是「# 转介话术（RX-033）…操作步骤…关键话术…」。AI 拿到的 `heading` 和界面展示的来源都会指向「禁止事项」。

### 5.7 文档标题是小节名（88 篇）

88 篇文档的标题形如「（一）结构与时长」「（二）关键设计要点」「（一）训练计划表」，其中「（一）结构与时长」有 3 篇同名但内容不同（分属 Think-Pair-Share、Round Robin、Numbered Heads Together）。检索命中后无法从标题判断语境，AI 也无法在回答里给出可定位的来源。

### 5.8 学段标注整片相同

| 模块 | 文档数 | 适用学部 |
| --- | --- | --- |
| self_growth | 317 | all |
| class_system | 415 | primary |
| student_case | 119 | primary |
| home_school | 102 | primary |
| learning_problem | 83 | primary |

719 篇整片标成「小学」，但内容本身并不都是小学专属（如「课堂接话茬的幽默化解」「三步行为契约」「家长抱怨的化解话术」）。`server/utils/stage-filter.ts` 的注释已经写明了这个风险：

> 试点初期内容整片标同一个学部时，过滤结果永远是「该学段全中」或「空集回退全部」，既没有分流收益，又让「为什么标了还都看得到」难以解释；等真的按学段拆分内容后再开。

**结论：`SCHOOL_SECTION_FILTER_ENABLED` 在学段标注整理完之前不应打开。**

### 5.9 检索实测（关键词分支，无需向量密钥）

对 9 个教师常见提问跑 `searchKnowledgeChunksHybrid`：

- self_growth 的召回结果里大量是**工具处方镜像**（《成功经验回溯（RX-066）》《转介话术（RX-033）》《积极反馈公式（RX-035）》《周末清零仪式（RX-047）》）——即三库工具库的正文，和 `resource_lookup` 的目录形成重复
- 命中的切片标题如上所述多为「禁止事项」「适用场景」
- 零命中时退到资源目录，而目录每个库只取前 6 条（`ASSISTANT_READER_LIMITS.catalogPerType = 6`）——self_growth 有 81 个工具，教师问「有没有相关工具」时，AI 看到的只是其中 6 个

> 本次未启用 embedding（无向量密钥），相似度列均为 0，属预期；向量分支的召回质量需要单独验证。

## 六、这些内容是怎么进入方案与 AI 对话的

### 6.1 方案链路（每一环都可验证）

```
三库发布版本 payload
  ├─ 分级规则 ──→ executeRules() ──→ level / levelName / severity / blocked   ← 决定方案走向与摘要
  ├─ 归因建议动作 ─→ actions[]：title「针对「X」」+ detail = suggestedAction  ← 直接展示
  ├─ 等级干预动作 ─→ actions[]：title「按「等级名」干预」+ detail             ← 86 条为空
  └─ 工具 structuredSteps ─→ renderToolContent() ─→ plans.tools[].content    ← 直接展示
                                    │
                                    ▼
                  enhancePlanActions()（后台 AI 改写，要求 100% 覆盖）
                                    │  未全覆盖 → aiActionsStatus=failed，保留三库原文
                                    ▼
                  plans.actions / plans.tools / plan_actions.detail 回写
                                    │
                                    ▼
                  ensurePlanActions()（读取时惰性补齐，按「标题+正文」判重）
```

已确认的线上缺陷：

**同一工具在同一方案里出现两次，一条是 AI 版、一条是机械版。** 41 个方案中有 9 个存在这种情况，重复分组 54 组。例（同一 plan）：

```
【row 7，AI 改写版】
不管正在做什么、说什么，先立刻停下来，像按了暂停键。然后做一次缓慢深呼吸，吸气4秒，呼气6秒。

【row 24，三库原文版，后补插】
1. S-Stop（停下来）：不管在做什么、说什么，立: S-Stop（停下来）：不管在做什么、说什么，立刻停下来。；T-Take a breath（深呼吸）：…；O-Observe（观察）：问自己——；- 我身体哪个部位有感觉？（胸口紧？脸发热？）；…
```

机制：AI 改写回写了 `plan.tools` 与已存在的 `plan_actions` 行，但 `plans.actions` 快照里仍是原文；读取时 `ensurePlanActions` 把快照（原文）和 `plans.tools`（改写版）合并，按「标题＋正文」判重，两版正文不同 → 判定为新动作并补插。`scripts/backfill-tool-action-steps.ts` 的注释记录过同一类问题，但只在脚本层面清理过存量数据，运行期的插重复路径没有关闭。

**AI 深度报告会继承这些问题文案。** `generateAssessmentReport` 的 `facts` 里包含 `levelName`、`attributions[].reasons`、`actions`（含 suggestedAction 原文）、`tools`（renderToolContent 原文）；同时 `jsonFormat` 传的是**确定性兜底报告本身**（其 `profile.summary` 正是 ④ 里那条「本次评估判定为黄色·中响应…」）。模型被要求按这个格式输出，等于把矛盾文案当作范例递给了它。

### 6.2 首页 AI 助手链路

```
教师提问 → Agent 图 → knowledge_search
                         ├─ 向量 + pg_trgm 混合召回，limit 5，minSimilarity 0.45
                         └─ 零命中退到 resource_lookup 目录（每库前 6 条）
```

- 召回池就是第五节里那 1036 篇：含三库派生文档、含 `${主要归因}`/`None`、含与引擎不符的阈值、含 78 篇写好的第一人称话术
- 切片的 `heading` 有 659 篇错配，来源展示与模型看到的标题都是错的小节名
- AI 回答平台正式内容（手册、量表、SOP、等级、制度）时只依据检索返回的结果，且被明确要求不得编造平台内容——**当检索返回的内容本身就是错的，模型越守规矩，越会把错误内容当成平台事实讲出去**
- `resource_lookup` 只给标题与一句摘要（`description` / `typicalTrigger`），所以 AI 对话受「建议动作」的直接影响小于方案链路，但受「知识库原文」的直接影响很大
